# AGENTS.md

Rules for anyone (human or agent) changing this repository. `CLAUDE.md` only points here,
so the rules cannot drift between tools. Keep this file short: a rule earns a line here only
if it prevents a mistake that happened, or one that a check cannot catch.

## What this is

saylist turns a small business's dialog (Telegram, WhatsApp, calls) into a structured catalog
that AI assistants reach through an API and an MCP server. Product code does not exist yet;
this repository currently holds only the foundation it will grow on.

Stack: Python 3.13, FastAPI, async SQLAlchemy 2, Alembic, Postgres 17, uv, ruff, mypy (strict),
pytest. Code, comments, docs and ADRs are in English.

## Layout

```text
AGENTS.md                 this file; the module graph below is the single source of truth
docs/adr/                 architecture decisions, one file each (see docs/adr/README.md)
docs/templates/           module README template
backend/app/core/         settings, database; imports nothing from modules or main
backend/app/modules/<m>/  one business module per folder (see "Modules")
backend/app/main.py       FastAPI entrypoint
backend/migrations/       Alembic, one linear chain for all modules
backend/tests/architecture/  the rules in this file, enforced
backend/scripts/          new_module.py, module_graph.py
```

## Commands

All from the repo root. CI runs exactly these targets, never copies of their commands.

- `make setup` installs dependencies and the git hooks. Run once per checkout or worktree.
- `make check` runs lint, format check, types and all tests that need no database. Run before
  every commit; it takes seconds.
- `make db-up` and `make migrate` start Postgres (port 5433) and apply migrations.
- `make test-db` runs the tests marked `db`. `make ci` is everything CI runs.
- `make new-module NAME=x` scaffolds a module and registers it in the graph.
- `make migration MSG="add catalog item"` autogenerates a migration. Read it before committing.

## Modules

A module is `backend/app/modules/<name>/`. Its purpose fits one sentence without "and".

- **The contract is `__init__.py`.** It has a docstring and an `__all__` listing what other
  modules may use: service functions, public schemas, enums, exceptions. Everything else in the
  folder starts with `_` (`_models.py`, `_repository.py`, `_service.py`, `_schemas.py`) and is
  private to the module.
- **Other code imports only the contract:** `from app.modules.catalog import add_item`, never
  `from app.modules.catalog._models import ...`. Need something that is not exported? Export it
  and document it in the module README; do not reach around.
- **Dependencies follow the graph below.** A module may import only the modules listed after its
  arrow. No cycles. Adding an edge is a design change: say why in the PR.
- **Tables belong to exactly one module** and are named after it: module `catalog` owns
  `catalog_*` tables; module `orders` owns `order` / `order_*` (singular is fine). The module
  README lists its tables. Other modules hold the id (with a DB foreign key) but no ORM
  `relationship()`, and never query another module's tables: they call its contract. (ADR 0001)
- **Inside a module:** the repository is the only place with SQL; the service holds the logic,
  takes an `AsyncSession`, calls `flush()` and never `commit()` (the request or job boundary
  commits); routers call services only.
- **Every module has a README** from `docs/templates/module-README.md`. Its goal: you can work on
  the module after reading only that file. "Invariants" is the most valuable section.

Each rule here is checked by `backend/tests/architecture/test_architecture.py`; the failure
message says how to fix it. Do not weaken a check to make a change pass: change the design or
ask.

## Database

- Money is an integer in minor units with a `_minor` suffix, next to a `currency` column. (ADR 0002)
- Enums are stored as VARCHAR (`native_enum=False`), so adding a value needs no migration.
- Every schema change is an Alembic migration, autogenerated and then read. CI fails if models
  and migrations disagree (`alembic check`) or if the chain has two heads.
- Never edit a migration that is on `main`; add a new one.

## Decisions (ADR)

Write an ADR in `docs/adr/` when a change alters the module graph, the data model's shape, or how
the system talks to the outside world, or when the obvious approach was rejected. ~40 lines;
template in `docs/adr/README.md`. ADRs are never rewritten: a new one supersedes the old.
Cite it in code where the choice looks odd: `# ADR 0002`. Read the index before designing.

## How to work

1. Find the owning module; read its README. New area? `make new-module` first.
2. Bottom up: model → migration → repository → service → schemas/router → tests.
3. `make check` until green. Update the module README (contract, tables, invariants) in the
   same commit as the code.
4. Branch per task, PR to `main`. Commits on `main` are refused by the pre-commit hook.
5. Several agents at once: one git worktree each (`make worktree NAME=x`), split work by files,
   not by topic. Only one branch at a time adds a migration.

## Checking your own work

Each rule exists because skipping it caused a wrong result. Add a rule only with the case
that caused it.

1. **A question is not a request.** "Can we do X?" gets an answer, not an edit.
2. **Show a new check failing** before you trust it passing: plant the violation, see red, remove
   it. Plant in a scratch copy, or remove it in the same command (`trap`/`finally`), so a
   crash cannot leave it in the tree.
3. **Test the consumers of a change, not only the change.** Who calls this function, reads this
   column, renders this field?
4. **Start from fresh `origin/main`.** Fetch and grep before building; the feature may exist.
5. **After a rename, grep for the old name** across code, docs and tests.
6. **"Not found" needs the search shown**, untruncated. A filter that matches nothing looks the
   same as success: `cmd | grep x` hides the exit code of `cmd`.
7. **Before writing a fact down, find where it is already written.** One source per fact; link
   to it instead of copying.
